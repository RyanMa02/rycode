# rycode-core 生产级 Harness 差距 Backlog

> 目的：记录 `rycode-core` 从当前 MVP 演进为生产级 Agent Harness 核心抽象层时需要逐步解决的问题。
>
> 说明：本文档是问题跟踪清单，不是一次性实施计划。后续每个问题应在真实模块开发时结合 `DESIGN.md` 细化设计、补充测试，再分阶段实现。

## 推进原则

- 不提前预设字段、参数或错误分类；等相关模块出现真实使用场景后再补充契约。
- 优先锁定已有行为，再扩展新抽象。
- 每次只解决一个明确问题；先补契约测试，再做最小实现。
- 修改架构边界、MVP 范围或长期约束时，同步更新 `DESIGN.md`。

## 优先级定义

- `P0`：核心安全、稳定性或运行时边界问题，应优先解决。
- `P1`：生产级扩展能力问题，会影响后续 CLI、REST、MCP、多代理、上下文等能力演进。
- `P2`：契约完善、可观测性增强或测试补强问题，可在 P0/P1 基础稳定后推进。

## 关键决策记录

### 不提前预设参数

后续优化不应为了“生产级”提前加入暂未消费的字段、参数、错误码或配置对象。优先保持 MVP 抽象简单，等真实模块开发产生明确需求后，再补充最小契约。

### 模型调用异常重试与恢复（P0）的边界

模型调用异常重试与恢复分为两层：

- **模型侧**：负责真实 provider 调用、超时、重试和 provider 异常归一化。该部分应放在真实 `ModelClient` 实现中，当前接口阶段不提前实现。
- **core 侧**：负责定义模型失败对 agent loop 的影响，包括 run 如何结束、后续如何事件化、如何与 session/store/resume 对接。

结论：**重试在 model，恢复语义在 core；模型侧重试排在真实 `ModelClient` 实现之后。**

## 建议推进顺序

1. 先补已有行为的契约测试，锁定当前 agent loop、工具失败、消息顺序和边界异常语义。
2. 继续收敛 P0 中已出现真实需求的问题，不为尚未开发的模块提前加参数。
3. 当真实 `ModelClient`、Session/Runtime、Event/Store、Context/Memory 等模块开始实现时，再回到对应条目细化设计。
4. 每解决一个问题前先补测试，再做最小实现，必要时同步更新 `DESIGN.md`。
